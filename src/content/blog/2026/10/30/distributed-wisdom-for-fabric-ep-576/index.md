## News & Announcements

- **[DAX LLM Benchmark v2.0 trailer](https://www.sqlbi.com/tv/dax-llm-benchmark-v2-0-trailer/)**. SQLBI's benchmark measures how well language models handle DAX. Tests are single-attempt queries with no special tools or skills, so agents cannot iterate. The hosts relay Marco Russo's view that AI is now practical for DAX development and that complexity is less of an obstacle, then look at how models rank over time and how some models think too much for simple tasks.

- **[Govern your Microsoft Fabric data estate from one place with the OneLake catalog](https://community.fabric.microsoft.com/blog/fbc_fabricupdatesblogs/govern-your-microsoft-fabric-data-estate-from-one-place-with-the-onelake-catalog/5377369)**. The OneLake catalog gives visibility across the estate with governance health metrics and actionable recommendations, including coverage of sensitivity labels, domains and tags, governance policies, and endorsements and certifications. The hosts note that the post pairs it with a skill and recommends the GitHub Copilot CLI, while any compatible coding agent works, which they like as a bring-your-own-agent approach.

## Main Discussion

**Topic:** Distributed wisdom for Fabric: the ability of an organization to connect experiences, knowledge and judgments scattered across people and teams so they shape decisions beyond where they originated.

### This or That

Before the main topic, Mike announces This or That, a daily game built entirely as a Fabric app. Each visit asks three new questions that are only open that day, shows how the community answered, lets you add your own option, and has a calendar to review earlier days.

### Wisdom across agents

The new challenge, they say, is distributing wisdom across all of your agents and teams of agents, including coding best practices. With agents speeding up development, teams can afford to apply good practices when writing code.

### Skills, tests and shared context

They debate whether skills are what make a report meet company standards. Mike argues the measure is whether you can write tests for what the report should be, and says report consistency comes from a theme file where each visual ties to one style. Both agree an ongoing project needs a shared brain, so the same skills and context are used by everyone and every agent.

### Where the advantage comes from

Once everyone adopts agents the playing field levels, and what differs is the unique skills, integrations and custom systems you have built. The hosts describe agents as part of a shared intelligence, where anything shared with the team is available to the agent, and recommend turning routine work into workflows or skills for agents.

## Looking Forward

Start by deciding where your team's skills and context live so every person and agent uses the same ones, and write tests for what a good report or pipeline looks like instead of relying on any one person's setup.
