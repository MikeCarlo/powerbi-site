What does it actually mean for data to be AI ready? Mike Carlo and Tommy Puglia use James Serra's three-part series as a guide, then debate where business context should live: in the semantic model, in data agent instructions, or in skills at the agent level.

## News & Announcements

- **[Full Design Using Power BI Desktop Bridge](https://www.meetup.com/chicagolandpowerbi/events/316158549/)**. Tommy hosts the Chicago Fabric / Power BI User Group on Thursday, November 19 at the Microsoft Technology Center on East Randolph Drive in Chicago. The session runs the full loop live with the Power BI Desktop Bridge (preview), a local server inside Power BI Desktop that lets agents like Claude and Copilot edit report files, reload Desktop, screenshot the page and fix their own render. Mike says giving the agent a prototype of the report makes it much easier for the AI to understand his intent.

- **[Use OneLake as native storage for Azure Databricks](https://community.fabric.microsoft.com/blog/fbc_fabricupdatesblogs/use-onelake-as-native-storage-for-azure-databricks-preview/5377939)**. OneLake external-location support lets Unity Catalog managed tables, volumes and views store their data directly in OneLake, while Azure Databricks keeps the compute and Unity Catalog governance. Mike talks about data gravity, since organizations are unwilling to move data once it lands, and the question he hears from clients about where the Databricks team ends and the Power BI and Fabric team begins.

- **[The next chapter for CI/CD in Fabric Warehouse (Preview)](https://community.fabric.microsoft.com/blog/fbc_fabricupdatesblogs/the-next-chapter-for-cicd-in-fabric-warehouse-preview/5401222)**. Fabric Warehouse CI/CD now covers DacFx-based schema deployment through Git and deployment pipelines, pre- and post-deployment scripts, and Warehouse Item Definition APIs, with fabric-cicd support and CI/CD for the SQL analytics endpoint planned. The hosts only call it out, but Mike says pre- and post-deployment scripts that create tables, make shortcuts, load data and run notebooks are something they have been asking for for years.

## Main Discussion

**Topic:** Making data AI ready, using James Serra's series [What Does It Mean to Make Data AI-Ready?](https://www.jamesserra.com/archive/2026/09/what-does-it-mean-to-make-data-ai-ready/), [Microsoft Tools for Making Data AI-Ready](https://www.jamesserra.com/archive/2026/09/microsoft-tools-for-making-data-ai-ready/) and [Prep data for AI vs. Fabric Data Agent Instructions: What Goes Where?](https://www.jamesserra.com/archive/2026/10/prep-data-for-ai-vs-fabric-data-agent-instructions-what-goes-where/).

### How the work is changing

The episode opens with Mike saying his days now hold more strategic thinking and less hands-on building, which suits him but leaves him exhausted by the end of the day. Tommy agrees, thinking of the hours he used to spend testing notebooks and DAX measures, and points to Skill Vault as something he envisioned and saw through without writing the code himself.

### What AI ready means

Tommy reads James's definition: data that is accurate and trustworthy, well described and documented, semantically clear, governed and secure, accessible, and enriched with business context so AI can interpret it correctly. Playing devil's advocate, he asks how data will ever be ready if data quality has always been the problem. Both agree that preparing data for AI without a clear purpose never ends, because you don't know what ready or done looks like. Tommy also pushes back on treating AI as a verb, since no organization says it "does data".

### Definitions, metadata and semantics

On business definitions, metadata and relationships, Mike says he is spending a lot of time on the Open Semantic Interchange (OSI) spec. He realized this week that a Power BI semantic model is really a physical model of real data, not a logical or conceptual one, and that if you don't describe things in a way an agent can understand, the agent gets worse at writing SQL and joining tables. He sees OSI and ontologies as the glue that describes how the same table in Databricks Unity Catalog, a shortcut to it, and a semantic model on top of that stitch together.

### Where do the instructions go?

James's third article on where instructions belong is where it gets fuzzy. Tommy notes that prep data for AI, data agent instructions, ontologies and the coming semantic views each hold instructions in different places, with no shared brain every tool reads the same way. Mike argues that business logic belongs with the semantic model and ontology so any tool connected to it gets the same instructions, while skills should cover things that span many semantic views, such as how to query a source. Tommy sees that cross-cutting context as a skill too, and they agree on the goal but not the delivery.

### Getting started

They close by sketching the steps for an organization: decide what problem you are solving and which tools and team members are involved, assess whether data quality is good enough, then cover governance and security. What the final product looks like, whether that is Claude in everyone's hands, data agents in Microsoft Foundry or a custom harness, is still an open question.

## Looking Forward

Pick a few real business questions and work out what someone new would need explained to answer them, then decide which gaps belong in the data, the semantic model, or agent instructions.
