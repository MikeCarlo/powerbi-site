Database Hub, announced at FabCon Barcelona, brings databases from Fabric, Azure and on-premises into one view. Mike Carlo and Tommy Puglia open it up, ask whether it is meant for DBAs, platform teams or BI teams, and share what they would want it to do next.

## News & Announcements

- **[Skill Vault](https://github.com/pugliabi/skill-vault)**. Tommy shares the latest Skill Vault update: it can create a shortcut, like a Windows Start menu app, so it opens in its own window, and on first startup a setup guide asks where to save your skills, what your targets are, and lets you sign in to Anthropic to use Claude without an API key. The release also includes bug fixes, and Mike calls out how useful it is to collect skills from across the internet, keep them in sync and keep them in one place.

## Main Discussion

**Topic:** [Database Hub in Fabric](https://techcommunity.microsoft.com/blog/azuresqlblog/database-hub-in-fabric-now-in-public-preview--turn-database-signals-into-guided-/4560846), a centralized experience for managing and monitoring databases across Azure, Fabric, on-premises and supported multi-cloud environments.

### Agents building the report

Before the main topic, Mike describes throwing a set of Excel files at an agent and being impressed by the dashboard it built, though he is not ready to tell anyone to skip Power BI. Tommy shares an example of asking for a bell curve of a baseball team's swing rate across five seasons to see whether one game was an outlier. Mike notes that a flat file was easier for the agent than a semantic model would have been, because the agent has to run DAX queries to see what is inside a column.

### What Database Hub is

Tommy gives the overview: Database Hub is in preview, and its main areas are overview, estate, performance, security and optimization. Mike likes that it reaches beyond the Fabric tenant to databases in your Azure subscriptions, covering Microsoft SQL, PostgreSQL and Cosmos DB, and on-premises or multi-cloud databases if they are registered with Azure Arc. He compares it to the monitoring hub, since you need one place to see which databases are running and which are close to capacity or being throttled.

### Who is it for?

Mike points out that his own Power BI work now runs on lakehouses, Direct Lake and SQL analytics endpoints, which do not show up in the hub. Tommy asks whether it is for DBAs, the platform team or the BI team. Mike thinks it is designed for DBAs, with security reviews, recommendations and performance views, while Tommy has déjà vu from the 2023 debates about whether data engineers would move into Fabric, and wonders whether DBAs would trust it enough to switch.

### First impressions

Looking at his own estate, Mike sees his Cosmos DB accounts and a Fabric SQL database, but not the storage and throttling details he expected. For now he calls it the "get your connection string quickly hub". He wants the workspace shown by default in the list, and while it opens in SSMS, VS Code and the Fabric editor, he asks where the option to open in VS Code for the web is.

### Agents and the bird's-eye view

Mike says more of his notebook work is now done by an agent while he checks the results, so he might rely on a scheduled agent run to monitor performance rather than the UI. Reading the skill that ships with the documentation, he worries that people will expect a "database hub" with a skill to dig deeper than a bird's-eye view. Still, he calls it a win and another tool in the toolbox.

## Looking Forward

If you manage databases across Fabric and Azure, open Database Hub and check what shows up, and use Azure Arc to bring in on-premises servers.
