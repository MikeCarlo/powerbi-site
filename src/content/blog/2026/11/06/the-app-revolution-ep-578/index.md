## News & Announcements

- **[OneLake: the file system for agent-first data engineering](https://community.fabric.microsoft.com/blog/fbc_fabricupdatesblogs/onelake-the-file-system-for-agent-first-data-engineering/5383035)**. The post treats OneLake as the file system, Fabric engines as applications and AI requests as terminal commands, so agents can work directly with assets. The hosts highlight the OneLake hosted MCP server, now in preview, which removes the need to install and maintain a local MCP server while the local one stays available. They like that the agent is told how the SQL engine, its endpoint and authentication work.

- **[Modernize data integration strategy with Microsoft Fabric when using Snowflake](https://community.fabric.microsoft.com/blog/fbc_fabricupdatesblogs/modernize-data-integration-strategy-with-microsoft-fabric-when-using-snowflake-a/5377581)**. A Fabric blog post on data integration for teams that also use Snowflake. It is one of the three news links in the episode description; the hosts spend more time on the other two.

- **[Bring your Fabric data into your next app with connectors](https://community.fabric.microsoft.com/blog/fbc_fabricupdatesblogs/bring-your-fabric-data-into-your-next-app-with-connectors/5377609)**. Fabric apps can connect to SQL databases, lakehouses, warehouses and Power BI semantic models, giving developers a consistent way to reach Fabric-managed data. The hosts discuss permissions such as read, read-write and execute, and an example where a browser app writes data back to a SQL database without the user signing in. They say the article needs more examples.

## Main Discussion

**Topic:** The app revolution in Fabric. Mike asks at what point an app becomes better than a report, since most people ask him for data and not for applications.

### From writing code to managing agents

The hosts describe moving from a technical leader who writes code to one who manages teams of agents, which means knowing good software design patterns and pushing them through agents and architectures. Mike also mentions training a client to build Power BI reports with an agent.

### Too many apps, and who builds them

They ask whether companies are creating too many applications. Mike compares it to the Power BI debate, where users were already building serious apps in Excel and Power BI made that more accessible and reusable. Tommy compares it to Power Apps, which still needed separate app builders and report developers.

### Do you need experience with agents?

They disagree on whether people without agent experience will build bad apps. One view is that this was true six months ago and less so now, since you can start with natural language and still get something impressive. Fabric apps working across licensing levels brings app building to more people in the organization.

### What to invest in

If creating an app costs almost nothing, the hosts argue the valuable work is the data environment around it, for example giving a marketing team a database they can write into that is optimized and has the data they need. Their conclusion is to build the pipelines, repositories and organized information so apps and agents can use them, and to check the code agents write.

## Looking Forward

Pick one request that would normally become a report and ask whether a small Fabric app with a SQL database behind it would serve the user better, then review the code the agent writes before you share it.
