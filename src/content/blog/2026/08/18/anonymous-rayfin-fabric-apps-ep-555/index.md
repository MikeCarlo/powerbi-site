## News & Announcements

- **[Chicago Fabric & Power BI user group — Fabric Task Flow Studio](https://www.meetup.com/chicagolandpowerbi/events/315711136/?eventOrigin=group_upcoming_events)** — Two days after this episode, Thursday, August 20, the group meets at 3 p.m. at the Microsoft office in downtown Chicago, and Tommy needs RSVPs by the end of Wednesday so every name is in the building system. The session walks through Fabric Task Flow Studio, the community tool built partly by Microsoft and partly by Alex Powers, which creates items from a single prompt and can manage a project you already have. September is already on the calendar, with October and November aimed at the Desktop Bridge and MCPs.

- **[Fabric Runtime 2.0 is generally available](https://community.fabric.microsoft.com/blog/fbc_fabricupdatesblogs/fabric-runtime-2-0-generally-available/5326359)** — Released about five days before the episode, Runtime 2.0 is the Spark-and-notebooks path Tommy points to for transforms when mirroring and shortcuts are not in play. The stack moves from Spark 3.5 to 4.1, with Delta Lake 4.2, Python 3.13, Java 21, and Scala 2.13, and Mike highlights liquid clustering plus the native execution engine (Gluten, with Velox), which you opt into per workspace or environment for more work on less compute, with no code changes and no extra cost. That engine becomes the default in late September, so he wants it tested first: a package that ran on Spark 3 has already failed a job for him on Spark 4, and a few minutes spent enabling the engine can still save heavy Spark users hundreds or thousands of dollars.

- **[SQL database skills for end-to-end Fabric solutions (preview)](https://community.fabric.microsoft.com/blog/fbc_fabricupdatesblogs/build-end-to-end-fabric-solutions-with-sql-database-skills-preview/5357234)** — About five days old, these skills live in Microsoft's Fabric skills collection and load only when the task needs them, while an MCP server or plugin stays present the whole session. General coding agents still miss Fabric's authentication and item-discovery APIs, so the skills teach an agent to create a SQL database — tables, keys, relationships, indexes, triggers, and sample data, plus schemas with vector columns — then explore, query, and check schema changes, from the GitHub Copilot CLI, Claude Code, Cursor, or Windsurf, using Entra and a Fabric API token. Mike still wants a GraphQL skill on the list, because the database can already expose a GraphQL API and an agent would rather call that than install a SQL driver.

- **[Anonymous data access in Fabric apps](https://learn.microsoft.com/en-us/fabric/apps/anonymous-data-access)** — The line Tommy reads from the article, its third sentence, is that anonymous access is an authorization option, not a replacement for authentication. A tenant admin has to enable it under Fabric apps (preview) before an app can give the anonymous role its own privileges on a table. Mike asked Microsoft for the feature about a month ago, and he still ranks it behind data that stays in Fabric and an agent that can build the app.

## Main Discussion

**Topic:** Anonymous data access in Rayfin, and why Mike ranks it third

A few episodes after the Rayfin sessions, and after Mike's Chicago user-group talk where he built more than one app, the missing piece showed up. About a month ago he tried to add a contact form, the agent told him it could not be done, and he asked the Microsoft team when it was coming. It is here, it is off by default, and both hosts spend the hour deciding what it is actually for.

- **Rayfin is the app. The data source decides what a stranger can do.** Standard Power BI visuals still miss interactions people ask for. Mike's example is a line chart with a brush that filters the rest of the page, which an agent can now build as a custom visual in a day or a weekend instead of weeks. A Fabric app goes further: the agent can use Vega, Plotly, or D3, against a SQL database that is read-write or a semantic model that is read-only and fast. Anonymous access matters on the SQL side, where someone with no account needs to insert a row.

- **The tenant admin has to turn it on.** In the admin portal, under tenant settings, Fabric apps (preview) now includes Anonymous data access. Mike likes that it ships disabled, because the people who run the tenant keep the decision. Tommy's first reaction is that the name sounds bad, and Mike treats that caution as reasonable.

- **It authorizes an operation for someone who is not signed in.** A normal Fabric app passes Entra identity through to the SQL database, so the app knows Tommy's email and row-level security can follow. Anonymous access is the case with no person attached: you allow the site to write a table anyway. Tommy stops the explanation to read the docs: anonymous access is an authorization option, not a replacement for authentication. The anonymous role and a signed-in role can carry different privileges, which is how a public form and a logged-in admin page can share one app. Mike's own picture is an admin page where you configure the questions, then a public page you embed in an iframe.

- **The wall it removes is the public write.** His examples are ordinary and specific. A company site that is almost entirely one-way, until the contact form. A Replit game, built while he learns the tool Microsoft is partnering with on Fabric apps, that should save a name and a score with no organizational login. A government page that today uses Publish to web, and now also needs parameters or a write. A utility outage map, which he wished he had during the hurricane that hit Chicago the week before: type an address, land the row, show the map, and leave the customer outside Entra. Microsoft Forms, in his view, embeds poorly and only lands in Excel. Google Forms embeds cleanly and lands in Google Sheets. Either path still means hauling a file into Fabric. A Rayfin form writes the SQL database, and a notebook can use the row immediately. Tommy adds the cost: that app consumes capacity units, which a Microsoft Form does not.

- **The toggle is a gap he hit while building, and a weak adoption pitch.** Tommy asks what you tell a technology manager, especially when the same database may hold private data, and when someone could hang a basic email-and-password page on anonymous access without Entra. Mike sets the pitch aside. Fabric apps are still short of what he can do with Azure Static Web Apps. He found this feature by hitting an obstacle, arguing with an agent for fifteen to thirty minutes, and recognizing a missing piece from the static-web world. Adopting Fabric apps because anonymous access exists is the sentence he refuses to say.

- **Gold is the data. Silver is the agent. Bronze is the anonymous user.** Both hosts land on the same podium. Gold: create, read, and write stay in Fabric, so he can stop moving rows between services. He is blunt that "Fabric as a backend" is the unimpressive part of the story; one system of record is the win. Silver: an agent can build the app from a screenshot and a description. Hand him Fabric apps with no agents and he would still use them, and he thinks most people will stop at the hundreds of lines of code, so he calls this the step after Power Apps, where you describe the app instead of clicking it together. Bronze: the anonymous user, necessary for the public case and last on the podium. Tommy expected the top two to swap, then agrees with Mike's order, and still thinks "prototype before lunch" sits closer to gold than Mike is allowing. The feature Mike wants next is a function layer, the piece he sees everywhere in Azure Static Web Apps, so an app can call external APIs and handle security there. He does not know if it is on the backlog. If it arrives, he says the medals get reordered.

- **Who maintains it is the objection he keeps hearing.** Customers ask what happens after an agent builds the app in half a day and something breaks. His answer is the same agent, as long as the project is in git: paste the complaint, pull the repo, ship the change. You still have to be able to tell the agent what you were building. Start on something small, live through a few debugging passes, and judge the maintenance story after that.

### External visitors stay outside the tenant

Mike's government and utility cases are people who will never have an Entra account in your tenant. Anyone who can open the app can do what the anonymous role allows, so that role belongs on the public table alone. When a page does need to know who the visitor is, he describes a second layer, a user table the app checks, rather than inviting every customer into Fabric. Tommy's question sits on top of that pattern: a technology manager should stay cautious whenever private data shares the database.

## Looking Forward

Pick one public write that has no business asking for an Entra account. Have a tenant admin enable Anonymous data access, put the anonymous role on that single table, and leave everything else on a signed-in role. Mike said he hopes to publish a build of an anonymous Fabric form in the next couple of days. Until that video is up, the order both hosts agreed on is the one to rehearse: data in Fabric first, an agent to build and fix the app, and anonymous access reserved for the visitor with no Entra account.
