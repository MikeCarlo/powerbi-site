## News & Announcements

- **[Enhanced data agent visualizations with Fabric visuals (preview)](https://community.fabric.microsoft.com/blog/fbc_fabricupdatesblogs/enhanced-data-agent-visualizations-with-fabric-visuals-preview/5359686)** — Microsoft is still pushing "ask a question, get a chart." Tommy flags the split the blog does not: Fabric apps and data agents do not share Power BI's visual library. A `show` verb triggers a visual, but you are now living with two standard visual stacks on one platform. Mike suspects Flint / Vega-Lite under the hood — one language, several renderers.

- **[Connectivity patterns in Microsoft Fabric](https://community.fabric.microsoft.com/blog/fbc_fabricupdatesblogs/connectivity-patterns-in-microsoft-fabric-a-guide-for-data-integration-workloads/5360180)** — A guide to integration and gateways. Mike's pyramid take: gateways were a top-three feature five years ago and now look like an aging all-star still in the lineup. FAB — Fabric as a backend — needs zero gateways because the data already lives there. The VNet gateway is the option he says still confuses people.

- **[Design the report from the meeting you already had](https://promptingbi.com/2026/08/19/design-the-report-from-the-meeting-you-already-had/)** — Tommy's write-up of the main-topic argument. A measure list is inventory, not a requirement. The spec is the stakeholder meeting: transcript, screenshots of a page you want to echo, and the metrics that conversation actually named. Freeze that into a brief with two to five decision questions before the agent touches a file.

- **[Power BI Desktop Bridge overview](https://learn.microsoft.com/en-us/power-bi/developer/agentic/power-bi-desktop-bridge-overview)** — The docs: a local JSON-RPC server inside Desktop, plus the CLI (`status`, `manifest`, `open`, `reload`, `screenshot`). Modeling MCP handles the semantic model; this handles the report.

## Main Discussion

**Topic:** How to use Desktop Bridge without getting inconsistent, out-of-sync reports

- **Install the CLI, not a custom integration.** They spend several minutes untangling terms. Desktop Bridge is the local server. The thing you install for an agent is the CLI package that talks to that server. Documentation puts it under the report-authoring skills; Claude will reach for the CLI because that is what the docs show.

- **It does not author in the service.** Bridge visualizes files already open in Desktop. A GitHub-connected report in the service is a different path. Do not expect screenshots of a workspace item you are not running locally.

- **Screenshots can be a lie.** Mike is already hitting this: the agent adds three visuals, the screenshot looks fine, and the PBIR on disk is a different version. Desktop's in-memory report and the files the agent edited have drifted. Check application state for unsaved changes before you trust the picture.

- **Same prompt, different page.** Tommy's complaint: ask for three measures over time and you get a new layout every run. That is not a reliable client workflow. Mike's reframe — it is usually the user, not the model. You asked for a report without giving the system a reusable design.

- **Napkin first, then Bridge.** Mike's pattern: build the page chrome — background, size, headers, footers — in a low-data mock, then tell Claude Code to turn that design into a standard the Desktop Bridge agent can reuse. Consistency comes from the skill, not from hoping the next oneshot lands.

- **A measure list tells the agent what is possible.** Forty measures in the model is not a requirement for an executive page that should show three. Tommy's article is the other side of the coin: without meeting context, you get a pretty report that does not answer the question.

- **Must-have skills, then slow down.** Skills for Fabric, plus Kurt Buhler's report/PBIR skills. Then spend time digesting how they work. Skip that and you will get garbage and blame the tool.

- **Pause and make a skill.** After "create this page / build a filter pane," do not start the next feature. Ask the agent to reflect. If you will do it again, have it write a skill. Claude Cowork is starting to offer that prompt at the end of a task.

### What agents unlock that the UI never did

Mike is no longer sure you should build one page at a time. Bookmarks, custom filter panes, and one-visual-per-page scratch pages used to be too painful to inspect. The agent can list every bookmark, explain what each one touches, and hide the experimental pages. He is still torn about the community rebuilding slide-out filter menus the product already has — but agents make that pattern cheap enough that it may stick.

Tommy's pushback: do not type a two-sentence prompt at Bridge and expect a shippable page. New work wants a larger prompt until the skills exist. Visuals have a wider "not wrong" space than code, which is why the brief and the screenshot loop matter more here than in a notebook.

## Looking Forward

Before the next Bridge session, write the decision questions from your last stakeholder meeting — then install Skills for Fabric and treat "reflect and save a skill" as a required step, not a nice-to-have.
